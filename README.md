# screeps-starter-go

A [Screeps](https://screeps.com) bot written in **Go**, compiled to **WebAssembly** with
[TinyGo](https://tinygo.org). Build and deploy are pure Go + TinyGo (no Node/npm).

Totally generated by LLM, not fully tested.

## Setup

You need [TinyGo](https://tinygo.org/getting-started/install/) (`tinygo version`) and Go.

```sh
cp screeps.sample.json screeps.json   # gitignored; add your token (or email/password for a private server)
```

## Build and deploy

```sh
./scripts/build.sh         # compile + assemble dist/ (no upload)
./scripts/push.sh main     # build + upload to the "main" destination in screeps.json
./scripts/push.sh sim      # also: pserver, season
```

## Check your changes

```sh
( cd go && go test ./lib/... ./brain/ )          # host tests; always name the packages
( cd go && GOOS=js GOARCH=wasm go vet ./... )    # vet the bot
node scripts/e2e.js                              # optional, after a build: one real tick with a mocked game
```

Plain `go test ./...` fails because `package main` and `go/screeps` import `syscall/js`.

## Where to write your bot

Edit **`go/brain/brain.go`**. `Tick(c, round)` runs once per game tick.

```go
func Tick(c *Ctx, round int) {
    if round != 0 { return }
    game := c.Game()

    sources := Filter(c.Sources(), func(s Source) bool { return s.Energy() > 0 })
    for _, cr := range game.Creeps() {
        if cr.FreeCapacity() > 0 {
            if src, ok := Closest(cr, sources); ok {
                cr.HarvestApproach(src, MoveGreenPath)   // harvest, or moveTo if out of range
            }
        }
    }
}
```

- **Read state** with the typed wrappers: `cr.Hits()`, `source.Energy()`, `g.Time`, `g.CPU.Bucket`,
  `room.Sources()`, `room.HostileCreeps()`. Reads are a snapshot from the start of the tick.
- **Act** with the action methods: `cr.Harvest(src)`, `cr.Transfer(...)`, `spawn.SpawnCreep(...)`.
  The `...Approach` variants also move toward the target when it is out of range.
  Actions are queued and run after `Tick` returns; their result codes arrive next tick (`c.PrevResult(i)`).
- **Ask the engine** (pathfinding, `find`, `look`, market, map): ask in round 0, read the answer in round 1+.
  ```go
  q := c.QRoomFind(...)            // round 0
  if c.Answered(q) { r := c.Answer(q) ... }   // round 1+
  ```
- **Helpers:** `Filter`, `Count`, `Closest` (same-room straight-line range, no pathfinding), `InRangeOf`, `RangeTo`.
- **Find the Go name for any Screeps API entry** in [`docs/api-coverage.md`](./docs/api-coverage.md).
- **Handles are valid for one tick only.** To refer to an object across ticks, store its id words
  (`IdA/IdB/IdC`) and look it up again with `c.FindByID`.
- **Logging** from Go is `println`.
- `brain` and `lib` must not import `syscall/js` (the host tests depend on it).

## Remembering things between ticks

Use `Mem`, a key-value store that survives global resets and code pushes. Keys are slash paths; values are
int, float, string or bytes.

```go
key := ObjKey("creep", cr.IdA(), cr.IdB(), cr.IdC(), "role")   // "creep/<id>/role"
Mem.SetInt(key, 3)
role := Mem.IntOr(key, 0)

Mem.SetStr("plan/W1N1", "expand")
Mem.Sweep("creep/", func(id string) bool { return alive[id] })   // drop entries of dead creeps
```

Also available: `Float`, `Bytes`, `Has`, `Delete`, `DeletePrefix`, `Keys(prefix)`.

The store is saved to RawMemory segments **90–93** (about 300 KB) whenever it changes, and restored
before the first tick of a new instance. Notes:

- Segments 90–93 are reserved. A `RawMemory.setActiveSegments` command from Go is overridden.
- If you change how the store is encoded, bump `StoreVersion` in `go/lib/store.go`; old data is then dropped.
- For small per-object numbers there are also four slots on each object (`cr.Mem0()`..`Mem3()`, set with the
  `Memory.set` op).

### Console

Type these in the in-game console to inspect the store:

| Command | What it does |
|---|---|
| `mem()` / `mem("creep/")` | print all entries, or those under a prefix |
| `memsize()` | entry count and encoded size |
| `memset("key", 5)` | write a number or string |
| `memdel("key")` | delete one key |
| `memclear("creep/")` | delete a prefix; `memclear("")` clears everything |

The first console command after a global reset fails; run it again next tick.

## Adding things

- **A property Go can't read yet:** add a column in `tools/spec_state.go` (a JS expression over `o`).
- **An options object** (moveTo options, spawn memory, find filter): add an entry to `PRESETS` in `js/host.js`
  and a constant in `brain` (see `MoveGreenPath`).
- After editing `tools/spec_*.go`, run `./scripts/build.sh`; it regenerates `go/lib/gen.go`,
  `go/lib/obj_gen.go`, `js/host_gen.js` and `docs/api-coverage.md`. Never edit those by hand.
- **A new JS module:** add it to the module map in `tools/main.go` (`upload`) and to `scripts/build.sh`.
- **CPU:** turn off object tables the brain doesn't read with `PACK.<kind> = false` in `js/host.js`.

## Layout

| Path | What |
|---|---|
| `go/brain/` | your bot logic |
| `go/lib/` | shared-memory plumbing, typed wrappers, `Mem`; `gen.go` and `obj_gen.go` are generated |
| `go/main.go`, `go/memio.go` | export glue between WASM and JS |
| `js/host.js` | packs the game, runs Go, answers queries, executes commands, persists `Mem` |
| `js/loader.js` | entry module: instantiates WASM once, sandbox polyfills, error recovery |
| `tools/` | build/upload tool and the API spec the generated code comes from |
| `go/screeps/` | optional `syscall/js` wrapper; not used by the default bot |

## Gotchas

- `-scheduler=none` (in `scripts/build.sh`) assumes a synchronous loop. If you add goroutines, channels,
  `time.Sleep` or `js.FuncOf`, remove it.
- Always build before uploading; `push.sh` does both.
- Never hand-edit `dist/wasm_exec.js`; the build re-copies and patches it. Edit the patch in `tools/main.go`.
- Debug anything at the JS/WASM boundary on the official server, not the Sim. The official isolate is
  stricter, and only it reports real CPU.

Design notes, the sandbox workarounds, and the performance model are in [`CLAUDE.md`](./CLAUDE.md).
